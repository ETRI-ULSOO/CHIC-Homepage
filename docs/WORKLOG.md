### 다이어그램 규칙 개정 (2026-08-03, 사용자 지적)

**초안 오류:** [[DESIGN]] 초안은 다이어그램을 "흰 배경 도판을 어두운 벽에 건다"로 규정했다. 근거는 *현행 다이어그램이 재색조 불가능한 흰 배경 PNG*라는 전제였는데, **재색조가 가능한 자산(직접 그린 SVG)에까지 그 제약을 적용한 것이 잘못**이다. 결과적으로 '연구개발의 필요성' 다이어그램만 페이지에서 색이 겉돌았다.

**개정:** 다이어그램은 시스템 팔레트 SVG로 재제작하는 것을 원칙으로 한다. 범주는 색이 아니라 위치·라벨로 구분하고 악센트는 Mint 하나만 쓴다. 흰 배경 원본과 재제작 SVG를 **같은 페이지에 섞지 않는다**(조각보 방지).

**실측:** 재제작 시 임의 회색(`#4d5a66`)을 각주·화살표에 썼다가 2.74:1로 기준 미달 확인. 각주는 토큰 `#93a4b3`(7.56:1), 화살표는 `#6b7b8a`(4.45:1, 비텍스트 3:1 충족)로 교정. **SVG 내부에도 토큰 강제 + 명암비 실측이 필요하다.**

### News · 리다이렉트 · 영문 다이어그램 · 폰트 · 배포 준비 (2026-08-03)

**News (5건)** — `src/content/news/{ko,en}/`, 목록 + 본문 페이지. 스키마 변경 2건:
- `date`를 **선택 필드로** 바꿨다. 현행 게시물 5건 중 2건(콜로키움 발표자료, 대전시립미술관)에 날짜 표기가 없다. **없는 날짜를 지어내지 않는다.** 표시할 때는 "날짜 미상"으로 대체한다.
- 날짜가 없으니 날짜 정렬로는 순서가 무너진다. `order` 필드로 현행 사이트의 게시 순서를 따른다.

**구 URL 리다이렉트 14종** — `astro.config.mjs`. 새 도메인에서 옛 경로를 입력해도 404가 나지 않는다. 국문 9 + 영문 5, 산출물 전수 확인.

**영문 다이어그램 7점 (M-10 해소)** — `*-en.svg`. 텍스트가 그림 안에 있으므로 언어별 파일로 존재한다. `diagramSrc()` 유틸이 로케일에 따라 경로를 고른다. **래스터였다면 불가능했을 작업이며, SVG 재제작의 실질적 이득이 여기서 나왔다.**

**폰트 자체호스팅 (M-09 해소)** — Google Fonts CDN 제거. `@fontsource/noto-serif-kr`(한글·라틴 400/600 서브셋) + `@fontsource-variable/playfair-display` + `pretendard`(가변·동적 서브셋). 빌드 산출물에 **외부 요청 0건** 실측 확인, 폰트 100개 파일 5MB(동적 서브셋이라 실제 다운로드는 일부만).

**Cloudflare Pages 배포 준비** — `public/_headers`(보안 헤더 + 해시 자산 영구 캐시), [[README]]에 빌드 설정 문서화. **대시보드 최초 연결은 계정 접근이 필요해 미수행.**

### ⚠️ 사고 기록 — 대외비 이미지 공개 (2026-08-05)

**무슨 일:** `robot-arm.webp`로 저장한 이미지가 로봇팔 사진이 아니라 **사업화 실적표 스크린샷**이었다. 표 안에 싣지 않기로 한 계약 상대 기관명(한국자산관리공사·서울역사박물관·포스트미디어·엔디에스 등)이 그대로 들어 있었고, 커밋 `d8e29e2`로 **공개 저장소에 push되었다.**

**원인:** 268건 이미지를 컨택트시트로 선별할 때 **라벨을 셀 하단에 그려** 다음 행 이미지의 라벨로 오독했다. 한 행이 밀린 상태로 12건을 매핑했고, 그중 4건이 잘못 배치되었다(사업화 표·Paired/Unpaired·색상 팔레트·지도 시각화).

**조치:**
1. `70e618a` — 파일과 참조 삭제, push
2. 컨택트시트를 **라벨을 이미지 위에 겹쳐 그리는 방식**으로 재생성 (`idx-*.jpg`)
3. 39건 전량을 재선별하고 **변환 전에 검증 몽타주로 육안 확인**
4. 빌드 산출물에서 계약 상대 기관명·금액 문자열 0건 재확인

**히스토리 재작성 실행 (2026-08-05, 사용자 승인):**

1. 전체 백업 번들 생성 (`chic-backup.bundle`, 4.2MB) — 저장소 밖 보관
2. 유출 blob을 **ID로 특정** (`2c0355ec…`, 141,968 bytes). 같은 경로의 현재 로봇팔 이미지(`9c703b42…`, 11KB)는 보존해야 하므로 경로 삭제가 아니라 blob 삭제를 택함
3. `git filter-repo --strip-blobs-with-ids` 실행 → 10커밋 유지, `d8e29e2` 이후 SHA 변경
4. 검증: 유출 blob 제거·현재 이미지 보존·빌드 통과·추적파일 107건 이상 없음
5. `git push --force` 완료 (`5370e02` → `0690a8e`)

**⚠️ force push만으로는 부족했다 (실측):** 옛 커밋 `d8e29e2`가 원격에서 SHA로 여전히 접근되고, 유출 파일이 **동일 해시·동일 크기로 그대로 다운로드된다.** GitHub는 도달 불가 객체를 자체 GC 전까지 보관한다. 사용자 판단으로 **저장소 삭제 후 재생성**을 택했으나, `gh` 토큰에 `delete_repo` 스코프가 없고 이 스코프는 브라우저 인증이 필요해 **비대화형 세션에서 수행 불가**. 사용자 직접 조치 대기.

**구 미해결 기술:** 삭제해도 `d8e29e2` 커밋에 파일이 남아 있어 **git 히스토리에서는 여전히 접근 가능하다.** 완전 제거하려면 히스토리 재작성(`git filter-repo` 등) 후 force push가 필요하며, 공개 저장소이므로 이미 클론·캐시된 사본까지는 회수할 수 없다. 사용자 판단 필요.

**교훈:** 자동 선별한 이미지를 그대로 쓰지 않는다. **변환 전에 대상과 라벨을 함께 눈으로 확인하는 단계**를 반드시 거친다. 특히 비공개 원본에서 뽑은 자산은 내용까지 확인해야 한다.
